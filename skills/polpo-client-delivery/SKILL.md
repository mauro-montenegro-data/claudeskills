## Purpose

Standardize how Polpo communicates delivery status, outcomes, and next actions to clients using concise and technical-but-accessible language.

## When to use

Use this skill when:
- converting technical execution into a client-readable delivery update
- drafting implementation/handoff notes with clear scope boundaries
- reporting blocked items, risks, and dependency ownership without ambiguity
- proposing immediate next steps with owners and sequence

Do not use this skill to make implementation decisions; pair with technical/operator skills first when needed.

## Working principles

- Be clear, concrete, and non-salesy.
- Separate delivered scope, pending scope, and blocked scope.
- State risks and dependencies explicitly with impact.
- Provide next steps with owners and suggested sequence.
- Use language understandable by technical and non-technical stakeholders.
- Avoid inflated claims or uncertain commitments.

## Output format

Return sections in this order:
1. Delivery summary
2. Completed items
3. Pending or blocked items
4. Risks and dependencies
5. Recommended next steps
6. Client-ready closing note

## Anti-patterns / what to avoid

- Ambiguous status language ("almost done", "nearly ready")
- Omitting blockers or dependency ownership
- Overly promotional tone
- Technical detail without business relevance
- Next steps without responsible owner suggestions
- Committing dates/scope that were not validated with the project team
